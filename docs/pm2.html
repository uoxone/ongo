PM2

More cores, same binary

OnGo serves in one process, like Django's runserver. PM2 starts that file again for each core you want to use.

Build first

On your machine:

ongo build nava

Upload the whole build/ folder. It must contain the binary and static/ next to it:

nava/build/nava
nava/build/static

In src/settings.rs, listen on every interface before you build again:

pub const ADDR: &str = "0.0.0.0:8000";

Install PM2

npm install -g pm2

Node is only for the process manager. The OnGo app stays a plain Linux binary.

One process

On the server, stand in the folder that holds the binary:

cd /var/www/nava
pm2 start ./nava --name nava

That is enough for a quiet site. Check it:

pm2 status
pm2 logs nava

Several processes

OnGo sets SO_REUSEPORT, so several copies can bind 0.0.0.0:8000 together. Pick a count close to your CPU cores — for eight cores, four or eight is fine:

pm2 start ./nava --name nava -i 4

Or match the machine:

pm2 start ./nava --name nava -i max

Each instance is its own process. The kernel shares new connections across them.

A small config file

Put ecosystem.config.cjs next to the binary:

module.exports = {
  apps: [
    {
      name: "nava",
      script: "./nava",
      cwd: "/var/www/nava",
      instances: 4,
      exec_mode: "fork",
    },
  ],
};

Then:

pm2 start ecosystem.config.cjs
pm2 save
pm2 startup

exec_mode: "fork" is required for a native binary. Do not use Node's cluster mode here. pm2 save and pm2 startup bring the app back after a reboot.

Day to day

CommandWhat it does
pm2 statusLists the processes
pm2 logs navaFollows stdout and stderr
pm2 restart navaRestarts every instance
pm2 stop navaStops without deleting
pm2 delete navaRemoves the app from PM2
pm2 scale nava 8Changes the instance count

After you rebuild

Copy the new build/ onto the server, then:

pm2 restart nava

Keep running PM2 from the folder that contains both ./nava and static/. OnGo looks for static files in the current directory first.

OpenLiteSpeed, systemd, or another supervisor works the same way: start several copies of the binary on the same address. PM2 is one convenient choice, not a requirement.
